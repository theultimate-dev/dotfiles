# 0010. Export a config-directory variable from `~/.zshenv`

## Status

Accepted

## Context

Yazi's `yazi.toml` has no include directive, so the stub mechanism of
[0001](0001-deliver-configs-as-include-stubs-not-symlinks.md) does not apply, and 0001 names a byte
copy as the fallback. Yazi resolves its config directory from `YAZI_CONFIG_HOME` before any
default, and its package manager writes `package.toml` and `plugins/` into that same directory. The
repository has no `zsh/` port yet, and `~/.zshrc` is regenerated wholesale by the private
installer. `~/.zshenv` is the file zsh reads for every shell, login or not, and nothing manages it.
The Herdr–Yazi plugin work needs a working Yazi before the shell port lands.

## Decision

We point Yazi at the repository's `yazi/` directory through a `YAZI_CONFIG_HOME` export in a named
block appended to `~/.zshenv`.

## Consequences

- A third redirect kind exists next to the include stub and the byte copy: an environment variable
  naming the repository directory.
- Yazi reads one directory, so there is no machine-local override file; an override is a later
  export below the block.
- Only a Yazi started from a zsh that read `~/.zshenv` sees the config; a GUI launcher sees the
  default, empty directory.
- `ya pkg` writes third-party plugin code into the repository tree; `yazi/plugins/` is ignored,
  `yazi/package.toml` is tracked, and `setup.sh` restores from it.
- A fresh clone needs the network once, in `setup.sh`, before Yazi has its plugins.
- `~/.zshenv` is a shared destination under the block contract of
  [0006](0006-manage-shared-destinations-with-delimited-blocks.md); the block is appended because
  the last export wins.
- [0005](0005-install-agent-tooling-without-managing-its-config.md) stands: Yazi is neither an
  agent nor an editor, and it never rewrites its own config.
- The shell port, when it lands, inherits this block; it does not move to `~/.zshrc`.

## Alternatives Considered

- Byte copy into `~/.config/yazi` — the repository stops being live, and every `ya pkg` run would
  report drift.
- A block in `~/.zshrc` — regenerated by the private installer, and read by interactive shells
  only.
- `~/.zprofile` — login shells only; a non-login zsh spawned by Herdr or Zed misses it.
- Waiting for the zsh port — blocks the Herdr plugin work on an unrelated change.
- A `dofile` stub for `init.lua` only — the TOML files still need a copy.
